# System Spec — what is actually built

Describes the implementation as it stands. Where it differs from `01_CANONICAL_GDD.md`, **this file and `DECISIONS.md` win**. Update this file in the same change that alters a rule.

## Architecture
- `src/engine/` — pure TypeScript, deterministic (`rng.ts`, seeded), no DOM/React. Combat: `combat.ts` (`applyPlayerAction`, `startBattle`), `damage.ts`, `targeting.ts`, `intents.ts`, `army.ts`, `heroStats.ts`, `data/{cards,units,heroes,relics}.ts`.
- `src/engine/run/` — run layer. One reducer, `applyRunAction(run, action)` in `runEngine.ts`. Phases: `choosing_starting_relic | on_map | in_battle | reward | event | merchant | city | defeat | run_complete`.
- Persistence: the whole `RunState` JSON in localStorage key `aod_run_state_v1`. No server (the GDD's PHP / server authority is not built).
- Combat state carries a cumulative `log: CombatEvent[]`; the UI derives feedback from newly appended events.

## Combat
- **Board.** 6v6. Positions 1–3 are the front row (left/center/right), 4–6 the back row sharing lanes (1&4, 2&5, 3&6).
- **Turn.** Player turn, then `END_TURN`, then enemy intents resolve, then the next player turn. Mana refills each turn. Hand: 5 cards on turn 1, +3 each later turn, max 10. Unplayed non-`retain` cards are discarded at end of turn. Block resets each player turn.
- **Free basic action.** Each stack acts once per turn (`actedThisTurn`): attack, or heal for the Priest. Costs no Mana.
- **Targeting (AO-D002).** Ranged (`rangedAllAccess`) units hit any living enemy. Melee: AO-D013 first (front row only while any front stack lives; the backline opens only when positions 1-3 hold no living stack, a single dead front lane exposes nothing), then AO-D021 lane rule (Taunt targets obey both rules too, AO-D032): a melee unit reaches only its own or an adjacent lane (left hits left+center, center all three, right center+right; left never reaches right), in both rows. **Disciples (AO-D033):** a melee stack in the back row with a living friendly stack directly in front of it (4->1, 5->2, 6->3) has no targets at all (`isBlockedByFrontAlly`, also passed as `ownArmy` to `computeValidTargets`; the UI can grey these stacks out); an empty front slot frees it, ranged units are unaffected, enemies obey the same rule (blocked enemies plan no attack). Basic actions and unit cards from a blocked stack are rejected. **Softlock guard (AO-D038, global):** a stack that reaches nothing simply does not attack ("has no target in reach") - an enemy right-lane unit never hits the player's last left-lane unit while any unit can still act. Only a TRUE stalemate (`isStalemate(playerArmy, enemyArmy)`: no living unit on either side has a legal target under the strict rules, ranged included) opens the fallback: then `computeValidTargets` (when given `ownArmy`) returns the nearest lane's candidates for both sides. Without `ownArmy` the function is strict (no fallback). Taunt narrows enemy targeting among reachable targets only (AO-D032). `untargetable` stacks are skipped.
- **Health model (AO-D004).** `maxHp = count x hpPerUnit`. Damage lowers `currentHp` and `count = ceil(currentHp / hpPerUnit)`. Block absorbs first. Healing adds HP, capped at `preBattleMaxCount x hpPerUnit`: each `hpPerUnit` of heal restores one soldier, never above the pre-battle count. A heal never lowers HP or count (a stack already above the cap heals 0). An effect that follows a lethal effect on the same card skips cleanly when its target is dead. Casualties persist into the run army; stacks reduced to 0 are dropped from it at the start of the next run action, so a later recruit/split never reuses their stackId. Relic army-size effects (Royal Banner, and the found Arcane Crystal) update `count`, HP, `startingCount` and `preBattleMaxCount` together.
- **Damage (AO-D018 + AO-D031, Heroes 3 model B).** Each unit has a base `damage`; `A = attack (+ Strength/relic flat - Weak)` and `D = (defense + passive + armor) / moraleDefense` only feed the modifier: `mod = 1 + min(3, 0.05 x (A-D))` if `A > D`, else `1 - min(0.7, 0.025 x (D-A))`. `raw = max(1, round(damage x heroEffectiveness x mod x count x cardAndOtherMultipliers))` (a landed hit never deals 0), linear in count, then Block. Base damage: Swordsman 1, Archer 3, Knight 4, Priest 1, Goblin 1, Orc 2, Shaman 1, Wolf 2. Constants in `damage.ts` (`ATTACK_ADVANTAGE_*`, `DEFENSE_ADVANTAGE_*`). Heals are linear in count too (AO-D034). Hero effectiveness `1 + max(0, stat-10) x 0.02`, capped x1.40 (STR melee, DEX ranged, INT magic, WIS healing). Dodge (player side) `max(0, DEX-10)%`, cap 20%. Max Mana `base + floor(max(0, WIS-10)/2)`, cap 12.
- **Defense buffs.** A card's "+N% Defense" becomes an `armor` status of `max(1, round(max(2, baseDefense) x N/100))` (sign preserved), never a flat N.
- **Morale** 0–100, starts 100: damage x0.7–1.0, defense x0.85–1.0. **Veterancy** tiers 0–3 give +0/3/5/8% damage.
- **Statuses (player-visible):** strength, weak, armor, bleed, poison, burn, fear, taunt, freeze. Poison/bleed/burn tick real damage at the start of the owner's turn; durations tick down each round.
- **StackFlags (internal, not statuses).** `cannotAttack`, `cannotMove`, `incomingDamageReductionPercent` expire at the start of the owner's next turn (AO-D005). Protect's `redirectPercent` / `redirectToStackId` are consumed by the first hit they redirect. `divineShield` is consumed by the first lethal hit (leaves 1 soldier). Counterattack is limited by `counterattackUsesLeft`. "Next attack" bonus flags clear after the attacker acts.
- **Passives.** Swordsman formation discipline (+10% defense next to a front ally), Archer high ground (+25% from the back row), Knight guard (25% redirect for adjacent front allies), Priest devotion, Goblin mob tactics, Orc brutal (+20% vs stacks under 50% count), Shaman support, Wolf pounce (+50% vs the back row).
- **Kill counts (AO-D022).** Every `STACK_ATTACKED` log entry carries `finalDamage` (HP through Block), `unitsKilled` and `countAfter`; the UI derives "-N units" / "Wounded" from them.
- **Enemy step list (AO-D023).** `END_TURN` still returns the atomic final `state`, plus `enemySteps: EnemyStep[]` in execution order: `{ actorStackId, kind: 'attack'|'buff', targetStackId, hits[] (attacker, target, hpDamage, blocked, unitsKilled, dodged, countAfter; counterattacks appear as extra hits), statuses[], resulting[] (count/currentHp/block of every stack the step touched) }`. Applying `resulting` in order reproduces the final army state (tested).
- **Enemy AI.** Intents are generated once at the start of each player turn from the live board (`intents.ts`); target score is baseline 30, +100 if lethal, +80 more if the lethal target is ranged/healer. The target pool uses the same geometry as the player's, so melee reaches the backline only once the whole player front row is dead (AO-D013). At resolution, intents whose actor died are skipped, and a planned target that died or left reach (the player repositioned) is retargeted only within the actor's legal targets (Taunt narrows the pool among reachable targets only, AO-D032). Intent data is **not shown to the player** (AO-D003) but drives the end-of-turn playback.
- **Cards.** 46-card pool (16 unit, 24 hero, 6 neutral). Effects are composable `CardEffect` data, not per-card code. Unit-sourced cards need a living stack of that unit; hero cards work regardless of army. Cost is Mana only. **Play conditions (AO-D040):** `cardRequirement(cardId)` returns short derived text ("Needs a living Knight and an enemy in reach") or null; sources are the card's source unit, tag-scoped effects (Mass Charge -> heavy = Knight, Venomous Army -> ranged = Archer), targeting `ally-stack+enemy-stack` (an enemy in reach) and `ally-stack+position` (a free position). `cardPlayability(cardId, state)` returns `{ playable, reason }` mirroring the engine's rejections (not the player's turn, source unit dead, not enough Mana, no stack has an enemy in reach, no stack can move / no free position, no target); the exact acting stack and target are still validated per action. `isCardActive` and `inactiveCardReason` are shared with the reducer.

## Run layer
- **Map.** 7 layers, 3 choices per layer. Node types: road, battle, elite_battle, resource, merchant, event, city, boss. One guaranteed city on layer 3. No Elite Battle on layers 1-3, the first 3 steps (AO-D039); elites only appear from layer 4. Moving costs food; starving kills units.
- **Start.** Hero (warlord/rogue/mage) with a 10-card, 4-distinct-card starting deck (AO-D028, AO-014: Warlord = Charge x3, Hold Formation x3, Hold the Line x2, Focus Fire x2; Rogue = Covering Fire x3, Ambush x3, Evasion x2, Focus Fire x2; Mage = Fireball x4, Arcane Shield x3, Heal x2, Focus Fire x1; no debuffs) and a small army (AO-D007), one starting relic chosen from a separate pool of exactly 5 (`STARTING_RELIC_DEFINITIONS`, AO-D037): Royal Banner (+6 to the largest stack), Whetstone (+10% damage), Padded Vest (-8% damage taken), Lucky Charm (+5% dodge), Traveler's Purse (+50 Gold once at start, effect `GOLD_FLAT`; AO-D043). Gold 100, Food 50, Day 1.
- **Rewards (AO-D006, AO-D026).** After victory: up to 3 choices total from new cards plus in-deck upgrades (`CARD_UPGRADES` is empty today, so 3 new cards). No relics after normal battles; an ELITE victory adds one extra relic offer (`pendingReward.relicOffer`, drawn last from the found pool with elite weights, never an owned relic). `CLAIM_RELIC { relicId }` grants it without closing the screen; the normal pick or skip closes it and forfeits an unclaimed relic. There is no confirm step: `CLAIM_CARD`, `CLAIM_UPGRADE`, `REMOVE_CARD` or `SKIP_REWARD` each resolve the reward at once (one pick only) and go to `on_map` (`run_complete` after the boss).
- **After a won battle (AO-D019).** Every surviving stack is restored to full HP of its surviving count; dead units stay dead. `startingCount` / `preBattleMaxCount` are reset to the new count, so heals in the next battle cap there. Starvation also lowers `preBattleMaxCount`.
- **Card removal (AO-D026).** `REMOVE_CARD { instanceId }`; rules and prices are the constants in `run/cardRemoval.ts` (values are proposals pending the owner's DDR answer): Reward = free and it is the reward's one pick; Merchant = Gold, price rises per use (50 + 25 x uses); City = free, once per 7 days (`run.day`). Deck floor 5 cards. `cardRemovalQuote(run)` tells the UI whether/what. Counters live in `run.cardRemoval`.
- **Run stats (AO-D027).** `run.stats` (`run/stats.ts`): enemiesKilled, unitsLost, unitsRevived, unitsRecruited, damageDealt, damageTaken (HP damage incl. overkill, after block), battlesWon, turnsPlayed, cardsPlayed, cardsRemoved, goldGathered, goldSpent, foodGathered, foodEaten (marching), largestStack, daysElapsed, nodesVisited. Combat numbers are folded from the events of each `COMBAT_ACTION`. Old saves: `migrateRun(run)` (also applied inside `applyRunAction`) fills zero defaults.
- **Merchant.** 3 cards at 50g and optionally one relic (weighted draw from the found pool, never an owned relic) priced by rarity, plus card removal.
- **Relics (AO-D037).** Every `RelicDefinition` has `rarity` (common/rare/epic); the description states any drawback. Found pool `RELIC_DEFINITIONS` (14; Arcane Crystal is rare, AO-D043) vs starting pool `STARTING_RELIC_DEFINITIONS` (5), disjoint. Prices `RELIC_PRICE_BY_RARITY` = 60/100/160 Gold and draw weights `RELIC_WEIGHTS` per source (merchant, elite, event) live in `run/relicSources.ts`, with `pickRelicId`. Drawbacks reuse existing effect kinds (`PLAYER_DAMAGE_TAKEN_MULT` > 1, `PLAYER_DAMAGE_MULT`/`TAG_DAMAGE_MULT` < 1, `HEALING_MULT` < 1, negative `HERO_MAX_MANA`, clamped so max Mana stays >= 1). "Melee" drawbacks use the `infantry` tag (Swordsman, Knight). `FIRST_CARD_DISCOUNT` remains declared but unimplemented (no relic uses it).
- **City.** Level 1–3 with 3/5/6 building slots (upgrade 150g / 300g). Recruit swordsman/archer/knight/priest straight into the army (max 6 stacks, same type merges), no garrison (AO-D008). A new type takes the first free slot (AO-D015). Buildings (AO-D020): market (recruit -15% Gold), gold mine (+10 Gold each day, on every move), mage tower (AO-D036: 3 tiers in one slot, cumulative hero max Mana +1/+3/+6 for 80/200/500 Gold; build = tier I, then `UPGRADE_MAGE_TOWER` per tier in order; `city.mageTowerTier` 0-3, numbers in `MAGE_TOWER_TIERS`; old saves migrate via `migrateRun`), stable (movement Food -25%, rounded down, min 1), training hall (+2 max Mana), forge (army attack +5% via the RelicEffect pipeline: `combatEffects` on the building definition), shrine (after each won battle 10% of each stack's casualties, rounded down, revive). One permanent doctrine at the Temple.
- **Reposition (AO-D015, AO-007).** `MOVE_STACK { stackId, toPosition }` works in `on_map` and `city` only (rejected in battle, reward, event, merchant). An empty target slot relocates, an occupied one swaps, the same slot is a silent no-op; no run event is logged. stackIds are opaque and stable: the initial `player_<unit>_<position>` is only a creation-time label, never re-derived from `position`. A split whose label collides with a moved stack gets a `_2`, `_3`... suffix so ids stay unique.
- **Events.** Small choice events with gold/food/HP/relic outcomes. Relic sources: Abandoned Camp Search (25% success, AO-D043; event weights) and Bandit Toll Refuse (`relicChance` 10% extra roll, Food cost unchanged; outcome `refuse_relic`).
- **Boss.** Currently a placeholder oversized Orc-heavy formation. The 3-phase Ashen Warlord is not built.

## Not built yet (GDD items still open)
Threat and dynamic encounters, Town teleport + 3-road return + 7-day recruitment, healing costs, Hero XP/leveling UI and traits, spatial dungeon with persistence, real boss phases, the full 15-relic roster (a subset exists), the card upgrade pool, server authority. Do not build these without a task.

## Known divergences from the GDD
- Enemy intent preview: GDD §20/§41 want it visible; the owner removed it (AO-D003).
- Melee backline fallback: GDD §4 allows the backline to become reachable; the owner forbids it for melee (AO-D002).
- Garrison and recruit-to-garrison: GDD §26 describes them; removed (AO-D008).
- Hero HP is hidden on hub screens (AO-D009); combat still tracks it (defeat at 0).
