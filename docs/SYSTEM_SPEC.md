# System Spec — what is actually built

Describes the implementation as it stands. Where it differs from `01_CANONICAL_GDD.md`, **this file and `DECISIONS.md` win**. Update this file in the same change that alters a rule.

## Architecture
- `src/engine/` — pure TypeScript, deterministic (`rng.ts`, seeded), no DOM/React. Combat: `combat.ts` (`applyPlayerAction`, `startBattle`), `damage.ts`, `targeting.ts`, `intents.ts`, `army.ts`, `heroStats.ts`, `data/{cards,units,heroes,relics}.ts`.
- `src/engine/run/` — run layer. One reducer, `applyRunAction(run, action)` in `runEngine.ts`. Phases: `choosing_starting_relic | on_map | in_battle | reward | event | merchant | city | defeat | run_complete`.
- Persistence: the whole `RunState` JSON in localStorage key `aod_run_state_v1`. No server (the GDD's PHP / server authority is not built).
- Combat state carries a cumulative `log: CombatEvent[]`; the UI derives feedback from newly appended events.

## Combat
- **Board.** 6v6. Positions 1–3 are the front row (left/center/right), 4–6 the back row sharing lanes (1&4, 2&5, 3&6).
- **Turn.** Player turn, then `END_TURN`, then enemy intents resolve, then the next player turn. Mana refills each turn. Hand: 5 cards on turn 1, +3 each later turn, max 10. Unplayed non-`retain` cards are discarded at end of turn. Block resets each player turn.
- **Free basic action.** Each stack acts once per turn (`actedThisTurn`): attack, or heal for the Priest. Costs no Mana.
- **Targeting (AO-D002).** Ranged (`rangedAllAccess`) units hit any living enemy. Melee: AO-D013 first (front row only while any front stack lives; the backline opens only when positions 1-3 hold no living stack, a single dead front lane exposes nothing), then AO-D021 lane rule with the AO-D044 fallback below (Taunt targets obey both rules too, AO-D032): a melee unit reaches only its own or an adjacent lane (left hits left+center, center all three, right center+right; left never reaches right), in both rows. **Disciples (AO-D033):** a melee stack in the back row with a living friendly stack directly in front of it (4->1, 5->2, 6->3) has no targets at all (`isBlockedByFrontAlly`, also passed as `ownArmy` to `computeValidTargets`; the UI can grey these stacks out); an empty front slot frees it, ranged units are unaffected, enemies obey the same rule (blocked enemies plan no attack). Basic actions and unit cards from a blocked stack are rejected. **Lane fallback (AO-D044, per attacker; replaces AO-D038):** the lane rule is a preference. From the AO-D013 candidate pool a melee attacker uses those within its own/adjacent lane; if none is in lane reach it may hit the nearest lane's candidates instead. So a lone corner unit (or a lone back-row unit once the front is empty) is hittable by every enemy melee unit whatever its lane, while any in-lane target still keeps melee from crossing to the far lane. No global stalemate check exists; `ownArmy` is only used for the AO-D033 block. Taunt narrows enemy targeting among reachable targets only (AO-D032). `untargetable` stacks are skipped.
- **Health model (AO-D004).** `maxHp = count x hpPerUnit`. Damage lowers `currentHp` and `count = ceil(currentHp / hpPerUnit)`. Block absorbs first. Healing adds HP, capped at `preBattleMaxCount x hpPerUnit`: each `hpPerUnit` of heal restores one soldier, never above the pre-battle count. A heal never lowers HP or count (a stack already above the cap heals 0). An effect that follows a lethal effect on the same card skips cleanly when its target is dead. Casualties persist into the run army; stacks reduced to 0 are dropped from it at the start of the next run action, so a later recruit/split never reuses their stackId. Relic army-size effects (Royal Banner, and the found Arcane Crystal) update `count`, HP, `startingCount` and `preBattleMaxCount` together.
- **Damage (AO-D018 + AO-D031, Heroes 3 model B).** Each unit has a base `damage`; `A = attack (+ Strength/relic flat - Weak)` and `D = (defense + passive + armor) / moraleDefense` only feed the modifier: `mod = 1 + min(3, 0.05 x (A-D))` if `A > D`, else `1 - min(0.7, 0.025 x (D-A))`. `raw = max(1, round(damage x heroEffectiveness x mod x count x cardAndOtherMultipliers))` (a landed hit never deals 0), linear in count, then Block. Base damage: Swordsman 1, Archer 3, Knight 4, Priest 1, Goblin 1, Orc 2, Shaman 1, Wolf 2. Constants in `damage.ts` (`ATTACK_ADVANTAGE_*`, `DEFENSE_ADVANTAGE_*`). Heals are linear in count too (AO-D034). Hero effectiveness `1 + max(0, stat-10) x 0.02`, capped x1.40 (STR melee, DEX ranged, INT magic, WIS healing). Dodge (player side) `max(0, DEX-10)%`, cap 20%. Max Mana `base + floor(max(0, WIS-10)/2)`, cap 12.
- **Defense buffs.** A card's "+N% Defense" becomes an `armor` status of `max(1, round(max(2, baseDefense) x N/100))` (sign preserved), never a flat N.
- **Morale** 0–100, starts 100: damage x0.7–1.0, defense x0.85–1.0. **Veterancy** tiers 0–3 give +0/3/5/8% damage.
- **Statuses (player-visible):** strength, weak, armor, bleed, poison, burn, fear, taunt, freeze. Poison/bleed/burn tick real damage at the start of the owner's turn; durations tick down each round.
- **StackFlags (internal, not statuses).** `cannotAttack`, `cannotMove`, `incomingDamageReductionPercent` expire at the start of the owner's next turn (AO-D005). Protect's `redirectPercent` / `redirectToStackId` are consumed by the first hit they redirect. `divineShield` is consumed by the first lethal hit (leaves 1 soldier). Counterattack is limited by `counterattackUsesLeft`. "Next attack" bonus flags clear after the attacker acts.
- **Passives.** Swordsman formation discipline (+10% defense next to a front ally), Archer high ground (+25% from the back row), Knight guard (25% redirect for adjacent front allies), Priest devotion, Goblin mob tactics, Orc brutal (+20% vs stacks under 50% count), Shaman support, Wolf pounce (+50% vs the back row).
- **Kill counts (AO-D022).** Every `STACK_ATTACKED` log entry carries `finalDamage` (HP through Block), `unitsKilled` and `countAfter`; the UI derives "-N units" / "Wounded" from them.
- **Enemy step list (AO-D023).** `END_TURN` still returns the atomic final `state`, plus `enemySteps: EnemyStep[]` in execution order: `{ actorStackId, kind: 'attack'|'buff', targetStackId, hits[] (attacker, target, hpDamage, blocked, unitsKilled, dodged, countAfter; counterattacks appear as extra hits), statuses[], resulting[] (count/currentHp/block of every stack the step touched) }`. Applying `resulting` in order reproduces the final army state (tested).
- **Enemy AI.** Intents are generated once at the start of each player turn from the live board (`intents.ts`); target score is baseline 30, +100 if lethal, +80 more if the lethal target is ranged/healer. The target pool uses the same geometry as the player's, so melee reaches the backline only once the whole player front row is dead (AO-D013). At resolution, intents whose actor died are skipped, and a planned target that died or left reach (the player repositioned) is retargeted only within the actor's legal targets (Taunt narrows the pool among reachable targets only, AO-D032). Intent data is **not shown to the player** (AO-D003) but drives the end-of-turn playback.
- **Cards.** 46-card pool (16 unit, 24 hero, 6 neutral). Effects are composable `CardEffect` data, not per-card code. Unit-sourced cards need a living stack of that unit; hero cards work regardless of army. Cost is Mana only. **Play conditions (AO-D040):** `cardRequirement(cardId)` returns short derived text ("Needs a living Knight and an enemy in reach") or null; sources are the card's source unit, tag-scoped effects (Mass Charge -> heavy = Knight, Venomous Army -> ranged = Archer), targeting `ally-stack+enemy-stack` (an enemy in reach) and `ally-stack+position` (a free position). `cardPlayability(cardId, state)` returns `{ playable, reason }` mirroring the engine's rejections (not the player's turn, source unit dead, not enough Mana, no stack has an enemy in reach, no stack can move / no free position, no target); the exact acting stack and target are still validated per action. `isCardActive` and `inactiveCardReason` are shared with the reducer.

## Run layer
- **Map and chapters (AO-D045, AO-D046, AO-D049).** The run is 3 chapters of 30 days; `run.chapter` (1-3), Day = world step counter. `generateWorldMap(rng, chapter, startDay)` builds one chapter: a `start` node (your position, layer 0), then 3 choices per layer, ending in a single `boss` node on the day `30 x chapter` (chapter 1 = 29 steps from day 1, chapters 2/3 = 30 steps). Node types: start, battle, elite_battle, resource, merchant, event, boss; there are no road or city nodes. No Elite Battle in the first 5 steps of the run (chapter 1 layers 1-5). Moving costs 1 day and the army's daily Food upkeep (see Food); starving kills units (see Food). Constants (days, warning, threat, depth, boss multipliers) live in `run/chapters.ts`. UI helpers: `daysUntilBoss(run)` (never below 0), `bossWarning(run)` (true at 7 days or fewer, i.e. from day 23), `bossDay(chapter)`. Encounter size scales with map depth (one step per 4 layers), +4 depth per later chapter, elite x1.3 and Threat.
- **Start.** Hero (warlord/rogue/mage) with a 10-card, 4-distinct-card starting deck (AO-D028, AO-014: Warlord = Charge x3, Hold Formation x3, Hold the Line x2, Focus Fire x2; Rogue = Covering Fire x3, Ambush x3, Evasion x2, Focus Fire x2; Mage = Fireball x4, Arcane Shield x3, Heal x2, Focus Fire x1; no debuffs) and a small army (AO-D007), one starting relic chosen from a separate pool of exactly 5 (`STARTING_RELIC_DEFINITIONS`, AO-D037): Royal Banner (+6 to the largest stack), Whetstone (+10% damage), Padded Vest (-8% damage taken), Lucky Charm (+5% dodge), Traveler's Purse (+50 Gold once at start, effect `GOLD_FLAT`; AO-D043). Gold 100, Food 50, Day 1.
- **Rewards (AO-D006, AO-D026).** After victory: up to 3 choices total from new cards plus in-deck upgrades (`CARD_UPGRADES` is empty today, so 3 new cards). No relics after normal battles; an ELITE victory adds one extra relic offer (`pendingReward.relicOffer`, drawn last from the found pool with elite weights, never an owned relic). `CLAIM_RELIC { relicId }` grants it without closing the screen; the normal pick or skip closes it and forfeits an unclaimed relic. There is no confirm step: `CLAIM_CARD`, `CLAIM_UPGRADE`, `REMOVE_CARD` or `SKIP_REWARD` each resolve the reward at once (one pick only) and go to `on_map` (`run_complete` after the boss). A boss victory before the last chapter adds `pendingReward.relicChoices` (3 unowned relics, epics first, then rare, then common because the roster has only 2 epics; `pickBossRelicChoices`): `CLAIM_RELIC` takes one (the rest are forfeited) without closing the screen. Resolving a boss reward (`run.bossBattle`) starts the next chapter (new map from the current day, `CHAPTER_STARTED`) or, after the 3rd boss, goes to `run_complete`.
- **After a won battle (AO-D019).** Every surviving stack is restored to full HP of its surviving count; dead units stay dead. `startingCount` / `preBattleMaxCount` are reset to the new count, so heals in the next battle cap there. Starvation deaths also reset `startingCount` / `preBattleMaxCount` to the new count.
- **Card removal (AO-D026).** `REMOVE_CARD { instanceId }`; rules and prices are the constants in `run/cardRemoval.ts` (values are proposals pending the owner's DDR answer): Reward = free and it is the reward's one pick; Merchant = Gold, price rises per use (50 + 25 x uses); City (AO-D052) = free the first time, then 50, 100, 200, 400 ... Gold (`cityRemovalPrice(cityUses)`: `CARD_REMOVAL.city.firstPaidGold x growth^(paid uses)`), no daily limit; unaffordable is rejected and quoted as not allowed. Deck floor 5 cards. `cardRemovalQuote(run)` tells the UI whether/what. Counters live in `run.cardRemoval` (`merchantUses`, `cityUses`; old saves with `lastCityDay` migrate to one city use).
- **Food (AO-D048).** Each unit has `foodPerUnit` in `data/units.ts` (Swordsman/Goblin 0.1, Archer/Priest/Shaman/Wolf 0.2, Knight/Orc 0.5). Daily upkeep = the sum of `count x foodPerUnit` rounded to the nearest whole Food, at least 1 for a living army (`moveFoodCost(army, city)`, `dailyUpkeep(run)`, per-stack `stackUpkeep(stack)`), Stable -25% (round down, min 1). Every move is one day: Farm Food is added first, then the army eats, then Gold Mine Gold; A day the stockpile (plus Farm) cannot cover the upkeep starves the army (AO-D057): Food becomes 0 (the army is not cut down to what it can feed) and units die. UI helpers: `dailyProduction(run)`, `dailyFoodNet(run)`, `foodDaysLeft(run)` (full days before starving, Infinity if net is not negative), `foodWarning(run)` (true when starving is at most `FOOD_WARNING_DAYS` = 3 days away, or the army is already starving). `DAILY_INCOME { gold, food }` carries the Gold Mine and Farm payout. Balance targets (tested in `ao022.test.ts`): a starting army (8 units, also with Royal Banner) lasts 15+ days on the starting 50 Food with no Farm; Farm I covers it; Farm III balances a 38-unit army and leaves a 60-unit army at -5 Food/day; Stable keeps cutting 25%.

  **Starvation (AO-D057, `run/food.ts`, all numbers in the `STARVATION` block).** On a starving day `shortageRatio = deficit / dailyNeed` (0-1], `run.starvationDays` += 1 and `deaths = min(units - 1, max(1, ceil(lossRate x units)))` with `lossRate = min(0.6, (0.04 + 0.08 x shortageRatio) x (1 + 0.5 x (starvationDays - 1)))`: a fully starved first day is 12%, a 10% shortage about 5%, and each further day adds +50% of the day-1 rate (18/24/30/36% at full shortage). Units die one at a time, each drawn uniformly among all living units with the run RNG (`starveArmy`), so deaths spread across stacks and are deterministic per run; the last unit never dies. Event `STARVED { deaths: {unitId, count}[], day, consecutiveDays }`. The first fully fed day sets `run.starvationDays` to 0 (old saves migrate to 0). Morale: from `moraleAfterDays` = 3 consecutive starving days every player stack starts battles at `100 - starvationMoraleMalus(days)` (-10 on day 3, -8 more per further day, capped at -100 = Morale floor 0, reached on day 14); it is applied to the combat army only (`startBattleForRun`), the run army keeps its Morale and a won battle does not bake the malus in, so it vanishes as soon as the streak resets. Combat reads Morale in `damage.ts` (`moraleDamageMultiplier` x0.7-1.0, `moraleDefenseMultiplier` x0.85-1.0, both clamped to Morale 0-100), so the malus is visible (day 5 -26: x0.92 damage, day 10 -66: x0.80 damage). UI helpers: `starvationForecast(run)` (`willStarve`, `shortageRatio`, `lossShare`, `expectedDeaths`, `consecutiveDays`, `moraleMalus`, `moraleMalusIfStarves`), `starvationLossRate`, `starvationMoraleMalus`. Survivors from 0 Food with every day fully starved (mean over 300 seeds, totals do not vary by seed): 8 units 7/5/3/2/1, 38 units 33/27/20/14/8, 60 units 52/42/31/21/13 after days 1-5, Morale malus 0/0/-10/-18/-26 (days 6-10: -34/-42/-50/-58/-66).
- **Battle loot (AO-D053).** After every won battle `rollBattleLoot` (run RNG, always 3 rolls) pays Gold plus a Food drop that is not guaranteed; event `BATTLE_LOOT { gold, food }` and the gathered stats are updated. Constants in `run/loot.ts` (`BATTLE_LOOT`, proposals): base band by chapter (Gold 12-24 / 25-45 / 40-70; Food chance 20% / 25% / 30%, Food 5-10 / 8-16 / 12-22), Gold and Food chance x(1 + 0.5 x share of the chapter's days gone), Threat multiplier on amounts, elite and boss Gold x1.75, Food chance x2 (capped 60%), Food x1.5. `battleLootBands(ctx)` gives the current bands for the UI.
- **Run stats (AO-D027).** `run.stats` (`run/stats.ts`): enemiesKilled, unitsLost, unitsRevived, unitsRecruited, damageDealt, damageTaken (HP damage incl. overkill, after block), battlesWon, turnsPlayed, cardsPlayed, cardsRemoved, goldGathered, goldSpent, foodGathered, foodEaten (marching), largestStack, daysElapsed, nodesVisited. Combat numbers are folded from the events of each `COMBAT_ACTION`. Old saves: `migrateRun(run)` (also applied inside `applyRunAction`) fills zero defaults.
- **Merchant.** 3 cards at 50g and optionally one relic (weighted draw from the found pool, never an owned relic) priced by rarity, plus card removal.
- **Relics (AO-D037).** Every `RelicDefinition` has `rarity` (common/rare/epic); the description states any drawback. Found pool `RELIC_DEFINITIONS` (14; Arcane Crystal is rare, AO-D043) vs starting pool `STARTING_RELIC_DEFINITIONS` (5), disjoint. Prices `RELIC_PRICE_BY_RARITY` = 60/100/160 Gold and draw weights `RELIC_WEIGHTS` per source (merchant, elite, event) live in `run/relicSources.ts`, with `pickRelicId`. Drawbacks reuse existing effect kinds (`PLAYER_DAMAGE_TAKEN_MULT` > 1, `PLAYER_DAMAGE_MULT`/`TAG_DAMAGE_MULT` < 1, `HEALING_MULT` < 1, negative `HERO_MAX_MANA`, clamped so max Mana stays >= 1). "Melee" drawbacks use the `infantry` tag (Swordsman, Knight). `FIRST_CARD_DISCOUNT` remains declared but unimplemented (no relic uses it).
- **City.** Level 1–3 with 3/5/6 building slots (upgrade 150g / 300g). Recruit swordsman/archer/knight/priest straight into the army (max 6 stacks, same type merges), no garrison (AO-D008). A new type takes the first free slot (AO-D015). Buildings (AO-D020): market (recruit -15% Gold), gold mine (+10 Gold each day, on every move), mage tower (AO-D036: 3 tiers in one slot, cumulative hero max Mana +1/+3/+6 for 80/200/500 Gold; build = tier I, then `UPGRADE_MAGE_TOWER` per tier in order; `city.mageTowerTier` 0-3, numbers in `MAGE_TOWER_TIERS`; old saves migrate via `migrateRun`), farm (AO-D048, AO-D058: 5 tiers in one slot, cumulative +3/+6/+9/+11/+13 Food each day for 60/140/320/560/900 Gold, `FARM_TIERS`; tier I covers the starting army, III a 38-unit army, IV a 60-unit army with a Stable, V a 60-unit army almost without one; build = tier I, then `UPGRADE_FARM` per tier in order, event `FARM_UPGRADED`; `city.farmTier` 0-5, old saves migrate to 0, `farmDescription(tier)`), stable (daily Food upkeep -25%, rounded down, min 1), training hall (+2 max Mana), forge (army attack +5% via the RelicEffect pipeline: `combatEffects` on the building definition), shrine (after each won battle 10% of each stack's casualties, rounded down, revive). One permanent doctrine at the Temple. Reachable any time (AO-D047, AO-D051): `TRAVEL_TO_CITY` from `on_map` enters the city (Threat +1, event `CITY_VISITED`), `LEAVE_CITY` returns to the same map node; a visit costs no days or food. `run.threat` scales enemy unit counts by `1 + 0.06 x threat` (`threatMultiplier`, `enemyStrengthAfterCityVisits(run, extraVisits)`; `CITY_VISIT_WARNING` is the warning text).
- **Reposition (AO-D015, AO-007).** `MOVE_STACK { stackId, toPosition }` works in `on_map` and `city` only (rejected in battle, reward, event, merchant). An empty target slot relocates, an occupied one swaps, the same slot is a silent no-op; no run event is logged. stackIds are opaque and stable: the initial `player_<unit>_<position>` is only a creation-time label, never re-derived from `position`. A split whose label collides with a moved stack gets a `_2`, `_3`... suffix so ids stay unique.
- **Events (AO-D050, D054, D055, D056; `run/events.ts`, appliers in `runEngine.ts`).** 16 definitions, drawn by `pickEventId(run)` (run RNG) as a weighted pool without repeats: `run.seenEventIds` records draws; chapter gates (`minChapter`) and a "some option is playable" filter apply; when every eligible event has been seen the history shrinks to the last `EVENT_TUNING.recentExclusion` (3) draws. Ids/weights: abandoned_camp 8, bandit_toll 8, wayside_shrine 8, plague_cart 8, hunters_lodge 8, deserter_knight 7, forgotten_library 7, fogbound_ford 7, cursed_well 6, crossroads_gallows 6, wandering_smith 6, ambushed_merchants 6, mercenary_camp 6, hedge_witch 5, ruined_watchtower 4 (chapter 2+), blood_altar 3 (chapter 2+). Every amount is a placeholder in `EVENT_TUNING`; Gold/Food scale x1 / x1.5 / x2 by chapter (`chapterScale`), units/days/Threat/chances do not. An option is `{ effects, gamble?, requires?, result }`. Effects: GOLD_DELTA, FOOD_DELTA, THREAT_DELTA (never below 0), UPKEEP_DAYS (Wait out fog, Join the hunt, Bandit Toll refuse: the Food the army eats in N days is paid at once, the calendar does not move, no Farm income; a shortfall runs the starvation model above, texts say "costs N days of food"), MAX_MANA_DELTA, UNIT_GAIN (fixed or `chosen`), UNIT_GAIN_ALL_STACKS, UNIT_LOSS (random/largest stack, count or percent, the army is never wiped), REVIVE_LAST_CASUALTIES (`run.lastCasualties`, set after each won battle net of Shrine revival, consumed by revivals), UPGRADE_CARD / REMOVE_CARD / GIVE_CARD (player picks the card), GAIN_CARD (random base card), RELIC (an event-weighted draw or rarity weights, +30 Gold when nothing is left), REVEAL_MAP (`worldMap.revealedUntilStep = current layer + steps`). UPGRADE_CARD marks `CardInstance.upgraded`; no card has an `upgrade` definition yet, so Study/Sharpen are always unavailable (see DDR in the AO-024 report). Requirements (`unit`, `gold`, `minDeckSize`, `minChapter`, plus implicit: an upgradable card, deck above `CARD_REMOVAL.minDeckSize` for remove/give, casualties to revive) are enforced in the reducer (reject with the reason) and exposed by `eventView(run)` / `optionAvailability(run, option)` as `available` + `reason`. Gamble (AO-D056): `{ successChance, success, failure: effects | 'ambush', ... }`; on `'ambush'` the event closes and a normal battle of the current chapter (current layer, current Threat, no bonus) starts, then the usual reward and back to the map. Gambles: Ambushed Merchants Rescue (30%, +Gold and a card), and, converted to ambush-on-failure, Blood Altar Smash (25% rare relic, Threat +1 either way) and Ruined Watchtower Loot the cellar (20% rare relic). Actions: `CHOOSE_EVENT_OPTION`; options needing a pick set `pendingEvent.choice` (`kind: 'card'` with eligible `instanceIds`, or `kind: 'unit'` with 2 random recruitable `unitIds` for Mercenary Camp) resolved by `CHOOSE_EVENT_CARD { instanceId }` / `CHOOSE_EVENT_UNIT { unitId }` or backed out with `CANCEL_EVENT_CHOICE`. Unit gain with no room (AO-D054): the newcomer waits in `run.pendingUnitChoice.newcomer` (a temporary 7th entry, placeholder position), `pendingEvent.resolved` holds the finished option, and the event closes only once `DISMISS_STACK { stackId, count? }` (any stack, the newcomer too; count omitted = whole; a whole dismissal that frees a slot places the newcomer; dismissing the last unit type is rejected) or `DECLINE_UNIT_GAIN` settles it; merging stacks that frees a slot also places it. `DISMISS_STACK` works outside battle in any phase (on_map, city, merchant, reward, event). `EVENT_RESOLVED` carries `outcome` (id) and `text` (English). Outcome ids: `search_relic`, `search_trap`, `refuse_relic`, `<option>_success`, `<option>_failure`, `<option>_ambush`, `<option>_nothing_left`, otherwise the option id. Retunes: Bandit Toll Refuse costs 2 days of upkeep (was 10 Food) with the 10% relic roll; Abandoned Camp Rest revives 30% of the last battle's casualties (was a hero heal; hero Mana refills every battle, so a Mana rest would do nothing). Old saves: `migrateRun` fills `seenEventIds`, `lastCasualties`, `pendingUnitChoice` and the event sub-state.
- **Boss.** A placeholder oversized Orc-heavy formation, scaled per chapter (`BOSS_CHAPTER_MULTIPLIER` 1 / 1.6 / 2.4) and by Threat; no new boss definitions yet. The 3-phase Ashen Warlord is not built. Old saves migrate (`migrateRun`) to chapter 1, Threat 0, a fresh chapter-1 map from their current day, and `finalBattle` becomes `bossBattle`.

## Known divergences from the GDD
- Enemy intent preview: GDD §20/§41 want it visible; the owner removed it (AO-D003).
- Melee backline fallback: GDD §4 allows the backline to become reachable; the owner forbids it for melee (AO-D002).
- Garrison and recruit-to-garrison: GDD §26 describes them; removed (AO-D008).
- Hero HP is hidden on hub screens (AO-D009); combat still tracks it (defeat at 0).
