# System Spec — what is actually built

Describes the implementation as it stands. Where it differs from `01_CANONICAL_GDD.md`, **this file and `DECISIONS.md` win**. Update this file in the same change that alters a rule.

## Architecture
- `src/engine/` — pure TypeScript, deterministic (`rng.ts`, seeded), no DOM/React. Combat: `combat.ts` (`applyPlayerAction`, `startBattle`), `damage.ts`, `targeting.ts`, `intents.ts`, `army.ts`, `heroStats.ts`, `data/{cards,units,heroes,relics}.ts`.
- `src/engine/run/` — run layer. One reducer, `applyRunAction(run, action)` in `runEngine.ts`. Phases: `on_map | in_battle | reward | event | merchant | village | city | defeat | run_complete`.
- Persistence: the whole `RunState` JSON in localStorage key `aod_run_state_v1`. No server (the GDD's PHP / server authority is not built).
- **Save format (AO-042).** `RunState.saveVersion` (`CURRENT_SAVE_VERSION` = 4, set by `createRun`); a save without it predates versioning and is version 1. `migrateRun` walks `MIGRATIONS[v]` one version at a time (`fromVersion1` holds every old field default, `fromVersion2` (AO-046) the fields added since: an unclaimed elite relic offer in a saved reward is granted and stored as `relicGained`; `fromVersion3` (AO-047, AO-D080) counts captured mines (`run.mines`, 0), moves the elites-defeated stat to `fortsTaken`, renames the logged `RESOURCE_FOUND` to `MINE_CAPTURED`, gives an unbuilt Barracks tier I and frees the building slot a built one held; before any step, `renameLegacyNodes` turns map nodes (and logged arrivals) `resource` into `mine` and `elite_battle` into `fort` for every save older than version 4, so the version-1 battle restart already rebuilds an old elite fight as a fort (node ids never carried a type); a current-version run is returned as is, never patched). Version 1 -> 2 also settles work in progress: a battle in progress is **restarted from its start** (same encounter rebuilt from the node, fresh combat; the run army is untouched during a battle, so nothing is lost and no fight is skipped), a pending reward keeps the options that still exist and is **re-rolled** when none are left. `validateSave(unknown): RunState | null` (`run/save.ts`) is the gate for storage reads: not an object, a version above the current one, a shape the reducer/UI cannot read (phase, army stacks, deck, hero, map, city, counters finite and whole, the phase's pending data present) or a migration that throws all return null, and the caller treats that as "no save".
- Combat state carries a cumulative `log: CombatEvent[]`; the UI derives feedback from newly appended events.

## Combat
- **Board.** 6v6. Positions 1–3 are the front row (left/center/right), 4–6 the back row sharing lanes (1&4, 2&5, 3&6).
- **Turn.** Player turn, then `END_TURN`, then enemy intents resolve, then the next player turn. Mana (AO-D065): a battle always opens at the hero's max Mana (`startBattle` resets it; the previous battle's leftover never carries) and it refills every player turn. **Battle end (AO-D067, AO-D079):** killing the last enemy sets `CombatState.enemiesCleared`; while the army has a living healer (a stack whose unit has the `heal` basic action, i.e. a Priest) the player may keep playing cards and healing and `END_TURN` then resolves the victory with no enemy turn; without a living healer the battle is won at once (also when a damage tick clears the field at a turn start). A wiped player army (or hero HP 0) still ends the battle at once. Hero-cast cards and cardPlayability reject with "No enemy to target." once the field is clear. **Frozen / cannot act (AO-D066):** `cannotAct(stack)` (`damage.ts`: freeze status or `cannotAttack` flag) means the stack neither gets an enemy intent (also dropped mid-turn when a card freezes it) nor acts on the enemy turn, and the player cannot use it for basic actions or attack cards; a stack frozen on the player's turn skips its next enemy turn and acts the turn after (statuses tick at the start of the next player turn). Hand: 5 cards on turn 1, +3 each later turn, max 10. Unplayed non-`retain` cards are discarded at end of turn. Block resets each player turn.
- **Free basic action.** Each stack acts once per turn (`actedThisTurn`): attack, or heal for the Priest. Costs no Mana.
- **Targeting (AO-D002).** Ranged (`rangedAllAccess`) units hit any living enemy. Melee: AO-D013 first (front row only while any front stack lives; the backline opens only when positions 1-3 hold no living stack, a single dead front lane exposes nothing), then AO-D021 lane rule with the AO-D044 fallback below (Taunt targets obey both rules too, AO-D032): a melee unit reaches only its own or an adjacent lane (left hits left+center, center all three, right center+right; left never reaches right), in both rows. **Disciples (AO-D033, amended by AO-D069):** a melee stack in the back row cannot attack while ANY living friendly stack stands in the front row, whatever the lane (`isBlockedByFrontAlly`, also passed as `ownArmy` to `computeValidTargets`; the UI can grey these stacks out); an empty front row frees it. Ranged units and support/healer units (`rangedAllAccess`, `basicAction: 'heal'` or tag `support`) are never blocked: a Priest heals from the back row, itself included. Enemies obey the same rule (blocked enemies plan no attack). Basic actions and unit cards from a blocked stack are rejected. **Lane fallback (AO-D044, per attacker; replaces AO-D038):** the lane rule is a preference. From the AO-D013 candidate pool a melee attacker uses those within its own/adjacent lane; if none is in lane reach it may hit the nearest lane's candidates instead. So a lone corner unit (or a lone back-row unit once the front is empty) is hittable by every enemy melee unit whatever its lane, while any in-lane target still keeps melee from crossing to the far lane. No global stalemate check exists; `ownArmy` is only used for the AO-D033 block. Taunt narrows enemy targeting among reachable targets only (AO-D032). `untargetable` stacks are skipped.
- **Health model (AO-D004).** `maxHp = count x hpPerUnit`. Damage lowers `currentHp` and `count = ceil(currentHp / hpPerUnit)`. Block absorbs first. Healing adds HP, capped at `preBattleMaxCount x hpPerUnit`: each `hpPerUnit` of heal restores one soldier, never above the pre-battle count. A heal never lowers HP or count (a stack already above the cap heals 0). An effect that follows a lethal effect on the same card skips cleanly when its target is dead. Casualties persist into the run army; stacks reduced to 0 are dropped from it at the start of the next run action, so a later recruit/split never reuses their stackId. Relic army-size effects (Royal Banner, and the found Arcane Crystal) update `count`, HP, `startingCount` and `preBattleMaxCount` together. A mid-run Royal Banner (only reachable through the pre-AO-D029 save migration) adds its units to the largest stack as healthy soldiers and keeps that stack's wounds. Mid-run (Arcane Crystal, x0.9) each living stack is floored but never below 1 unit and keeps its wounds (HP only capped at the new maximum, no heal). Per-battle state (flags, statuses, block, `actedThisTurn`) is cleared on every player stack when a battle starts and when it is won (`clearCombatState`); only count, HP, veterancy and morale persist. `untargetable` (Emergency Retreat) expires with the other 1-turn flags at the start of the owner's next turn. `PLAY_CARD` rejects a `targetStackId` that is not a living friendly stack on cards that do not target an enemy.
- **Damage (AO-D018 + AO-D031, Heroes 3 model B).** Each unit has a base `damage`; `A = attack (+ Strength/relic flat)` and `D = (defense + passive + armor) / moraleDefense` only feed the modifier: `mod = 1 + min(3, 0.05 x (A-D))` if `A > D`, else `1 - min(0.7, 0.025 x (D-A))`. `raw = max(1, round(damage x heroEffectiveness x mod x count x cardAndOtherMultipliers))` (a landed hit never deals 0), linear in count, then Block. Weak (`weakDamageMultiplier`) multiplies the final damage by `1 - amount/100` (AO-036; Shield Bash Weak 20 = -20% damage, was a flat -20 Attack). Base damage: Swordsman 1, Archer 3, Knight 4, Priest 1, Goblin 1, Orc 2, Shaman 1, Wolf 2. Constants in `damage.ts` (`ATTACK_ADVANTAGE_*`, `DEFENSE_ADVANTAGE_*`). Heals are linear in count too (AO-D034). Hero effectiveness `1 + max(0, stat-10) x 0.02`, capped x1.40 (STR melee, DEX ranged, INT magic, WIS healing). Dodge (player side) `max(0, DEX-10)%`, cap 20%. Max Mana (AO-D065) `baseMana + floor(max(0, WIS-10)/WISDOM_PER_BONUS_MANA)` (4), cap 12; `baseMana` is 3 for every hero, so fresh heroes start Warlord 3 (WIS 8), Rogue 3 (WIS 13), Mage 4 (WIS 16); Mage Tower, Training Hall, relics and events add on top.
- **Defense buffs.** A card's "+N% Defense" becomes an `armor` status of `max(1, round(max(2, baseDefense) x N/100))` (sign preserved), never a flat N. **Stacking (AO-045):** armor/strength buffs carry `sourceId` (the applying card): buffs from different cards add up, the same card played again refreshes its entry (longer duration, larger amount) instead of adding a copy, and `armorReduction` caps the total at `ARMOR_MAX` (8).
- **Hero-cast cards (AO-D064, AO-D074; `heroSpells.ts`).** `CardDefinition.cast = 'hero'` + `scalesWith` (strength/dexterity/intelligence): the hero casts on the chosen enemy (or all, `targeting: 'none'`), no acting stack or unit type, no damage to the player's stacks. Hits report `attackerStackId = HERO_ATTACKER_ID` ('hero'). `damage = round(HERO_SPELL_BASE_POWER (10) x card multiplier x heroSpellScaling(stat) x attackDefenseModifier(HERO_SPELL_ATTACK (5), target defense) x relic/execute multipliers)`, `heroSpellScaling = max(0.5, 1 + (stat-10) x 0.05)` (INT 18 -> x1.4, INT 8 -> x0.9). Hero-cast list: Fireball (INT, 2 Mana, 140% + 40% splash to the same-row neighbours), Frost (INT), Chain Lightning (INT), Arcane Storm (INT, none), Arrow Rain (DEX, none, now a Rogue card), Command: Strike (STR, 1 Mana, 80%), Volley (DEX, 1 Mana, 80%). Fresh Mage Fireball: 24 HP damage / 4 goblins, 24 / 3 wolves, 23 / 1 orc. **Army-wide buffs:** Focus Fire (`ARMY_NEXT_ATTACK_BONUS`, `CombatState.nextFriendlyAttackBonusPercent`, consumed by the first friendly attack), Formation (`DEFENSE_BUFF_ALL`), Rally (`GAIN_MORALE_ALL`), Battle Hardened (`DAMAGE_AND_DEFENSE_BUFF` scope army) and Hold the Line have `targeting: 'none'`.
- **Morale** 0–100, starts 100: damage x0.7–1.0, defense x0.85–1.0. **Veterancy** tiers 0–3 give +0/3/5/8% damage.
- **Statuses (player-visible):** strength, weak, armor, bleed, poison, burn, fear, taunt, freeze. Poison/bleed/burn tick real damage at the start of the owner's turn; durations tick down each round. `STATUS_INFO` / `statusEffectText(id, amount)` (`data/statuses.ts`, AO-036) is the single table of names, effect texts (built from the `damage.ts` constants) and buff/debuff kind for the UI.
- **StackFlags (internal, not statuses).** `cannotAttack`, `cannotMove`, `incomingDamageReductionPercent` expire at the start of the owner's next turn (AO-D005). Protect's `redirectPercent` / `redirectToStackId` are consumed by the first hit they redirect. `divineShield` is consumed by the first lethal hit (leaves 1 soldier). Counterattack is limited by `counterattackUsesLeft`. "Next attack" bonus flags clear after the attacker acts.
- **Passives.** Swordsman formation discipline (+10% defense next to a front ally), Archer high ground (+25% from the back row), Knight guard (25% redirect for adjacent front allies), Priest devotion, Goblin mob tactics, Orc brutal (+20% vs stacks under 50% count), Shaman support, Wolf pounce (+50% vs the back row).
- **Kill counts (AO-D022).** Every `STACK_ATTACKED` log entry carries `finalDamage` (HP through Block), `unitsKilled` and `countAfter`; the UI derives "-N units" / "Wounded" from them.
- **Enemy step list (AO-D023).** `END_TURN` still returns the atomic final `state`, plus `enemySteps: EnemyStep[]` in execution order: `{ actorStackId, kind: 'attack'|'buff', targetStackId, hits[] (attacker, target, hpDamage, blocked, unitsKilled, dodged, countAfter; counterattacks appear as extra hits), statuses[], resulting[] (count/currentHp/block of every stack the step touched) }`. Applying `resulting` in order reproduces the final army state (tested). The run layer's `COMBAT_ACTION END_TURN` result carries the same `enemySteps` (`RunApplyResult.enemySteps`, AO-036).
- **Enemy AI.** Intents are generated once at the start of each player turn from the live board (`intents.ts`); target score is baseline 30, +100 if lethal, +80 more if the lethal target is ranged/healer. The target pool uses the same geometry as the player's, so melee reaches the backline only once the whole player front row is dead (AO-D013). At resolution, intents whose actor died are skipped, and a planned target that died or left reach (the player repositioned) is retargeted only within the actor's legal targets (Taunt narrows the pool among reachable targets only, AO-D032). Intent data is **not shown to the player** (AO-D003) but drives the end-of-turn playback.
- **Cards.** 46-card pool (16 unit, 24 hero, 6 neutral). Effects are composable `CardEffect` data, not per-card code. Unit-sourced cards need a living stack of that unit; hero cards work regardless of army. Cost is Mana only. **Play conditions (AO-D040):** `cardRequirement(cardId)` returns short derived text ("Needs a living Knight", AO-D075: never "an enemy in reach") or null; sources are the card's source unit, tag-scoped effects (Mass Charge -> heavy = Knight, Venomous Army -> ranged = Archer) and targeting `ally-stack+position` (a free position). `cardPlayability(cardId, state)` returns `{ playable, reason }` mirroring the engine's rejections (not the player's turn, source unit dead, not enough Mana, no stack has an enemy in reach, no stack can move / no free position, no target); the exact acting stack and target are still validated per action. `isCardActive` and `inactiveCardReason` are shared with the reducer.

- **Card upgrades (AO-D060, AO-032; `src/engine/cardUpgrades.ts`).** Every card in the pool has one "+" version, kept in one table `CARD_UPGRADES` (`{ description, manaCost?, effects? }`; omitted parts stay as the base card has them). An upgrade is instance state: `CardInstance.upgraded`, set once by the reward Upgrade pick, Forgotten Library Study or Wandering Smith Sharpen (`isUpgradable` = has a "+" and is not upgraded yet). `resolveCard(cardId, upgraded)` returns the card as it plays (name "Charge +", upgraded cost and effects; source, tags, targeting, exhaust are the base card's); `applyPlayerAction` PLAY_CARD and `cardPlayability(cardId, state, upgraded)` read it, so Mana, effects and play conditions follow the instance. Rules, one per card: (a) cost -1 on a 2+ Mana card, or (b) the main numbers +25-40% (durations, conditions, thresholds and drawbacks untouched), or (c) one small extra effect (draw 1 more) on a cheap card whose numbers are already high. Never a new debuff, never a lost condition. Old `_plus` id-swap convention: not used (no such ids exist). The full list:

## Run layer
- **Map and chapters (AO-D045, AO-D046, AO-D049, AO-D076).** The run is 3 chapters of 30 days; `run.chapter` (1-3), Day = world step counter. `generateWorldMap(rng, chapter, startDay)` builds one chapter: a `start` node (your position, layer 0), then 3 choices per layer, ending in a single `boss` node on the day `30 x chapter` (chapter 1 = 29 steps from day 1, chapters 2/3 = 30 steps). Node types: start, battle, fort, mine, village, merchant, event, boss; there are no road or city nodes. Each layer draws its 3 nodes from `NODE_WEIGHTS` (`worldMap.ts`: battle 4, event 2, mine 1, village 1, merchant 1, fort 1). No fort in the first 5 steps of the run (`FORT_FREE_STEPS`, chapter 1 layers 1-5). Moving costs 1 day and the army's daily Food upkeep (see Food); starving kills units (see Food). Constants (days, warning, threat, depth, boss multipliers) live in `run/chapters.ts`. UI helpers: `daysUntilBoss(run)` (never below 0), `bossWarning(run)` (true at 7 days or fewer, i.e. from day 23), `bossDay(chapter)`. **Encounter size (AO-D078, `encounters.ts`, `chapters.ts`):** depth = `ceil(layer / LAYERS_PER_DEPTH (4))` + `CHAPTER_DEPTH_BONUS` (6) per later chapter; a fight fields `min(6, 1 + depth + ENCOUNTER_EXTRA_SLOTS (1))` slots (a fort 2 + depth + 1), each stack `base x (1 + depth x ENCOUNTER_DEPTH_SLOPE (0.08)) x Threat multiplier` (fort x1.3). **Fort (AO-D077):** the old elite renamed: same templates and strength; its victory grants a drawback-free relic automatically (Rewards) and pays fort loot (Battle loot); `stats.fortsTaken`. **Mines (AO-D076, `run/mines.ts`, constants in `MINE`):** arriving at a mine captures it at once (no fight, the run stays on the map): a one-off find (Gold 7-13, Food 3-7, x Economic Doctrine; about a third of the old free resource node), `run.mines` +1, `stats.minesCaptured`, event `MINE_CAPTURED { gold, food, mines }`. Every captured mine pays `MINE.dailyGold` (1) Gold each day in the daily hook (`mineDailyGold(run)`; only `MINE.payingMines` (6) count), added to the Gold Mine building's +10 in the same `DAILY_INCOME` event.
- **Villages (AO-D072, AO-046; `run/villages.ts`, constants in `VILLAGE`).** Villages are drawn into the chapter maps like every other node type (`NODE_WEIGHTS.village`). Arriving sets phase `village` and `run.pendingVillage` = `villageOffer(chapter)` (the numbers the choice pays, by chapter). `RAID_VILLAGE`: Gold 60/100/150 and Food 15/25/35 at once, Threat +1 (events `VILLAGE_RAIDED`, `THREAT_CHANGED`), `stats.villagesRaided`. `HELP_VILLAGE`: Gold 15/15/15 and Food 4/6/8, `run.villages` +1 (permanent, `stats.villagesHelped`, event `VILLAGE_HELPED { gold, food, villages }`); each helped village gives +1 Food a day (`villageDailyFood`, included in `dailyProduction` and the DAILY_INCOME event next to the Farm) and 1 Swordsman militia to the weekly garrison (`villageMilitiaPerWeek`, at most 2 villages count), which grows even without a Barracks. Both choices return to `on_map`. Village upgrades are out of scope.
- **Rewards (AO-D006, AO-D026).** After victory: up to 3 choices total: one in-deck upgrade (a random not-yet-upgraded deck card, `upgradeOptions`, claimed with `CLAIM_UPGRADE`, which sets `CardInstance.upgraded`) plus new cards to fill the 3 (2 new cards; 3 when nothing is upgradable). No relics after normal battles; a FORT victory grants one relic automatically (AO-D068, AO-D077): it is drawn last from the simple pool (found relics whose `drawbacks` list is empty, `isSimpleRelic` in `relicSources.ts`, weights `RELIC_WEIGHTS.fort`, never an owned relic; nothing is granted once the pool is used up), granted at the victory (event `RELIC_CLAIMED`) and stored as `pendingReward.relicGained` for the "Relic gained" banner. The reward can never be skipped and cannot remove a card (`SKIP_REWARD`, `REWARD_SKIPPED` and the reward-screen removal are gone) and always offers at least 2 new cards (`MIN_REWARD_NEW_CARDS`). There is no confirm step: `CLAIM_CARD` or `CLAIM_UPGRADE` resolves the reward at once (one pick only) and goes to `on_map` (`run_complete` after the boss). A boss victory before the last chapter adds `pendingReward.relicChoices` (up to 3 unowned simple relics, epics first, then rare, then common; `pickBossRelicChoices`, drawback relics never appear, so fewer than 3 may be left): `CLAIM_RELIC` takes one (the rest are forfeited) without closing the screen; it is the only use of `CLAIM_RELIC` now. Resolving a boss reward (`run.bossBattle`) starts the next chapter (new map from the current day, `CHAPTER_STARTED`) or, after the 3rd boss, goes to `run_complete`.
- **After a won battle (AO-D019).** Every surviving stack is restored to full HP of its surviving count; dead units stay dead. `startingCount` / `preBattleMaxCount` are reset to the new count, so heals in the next battle cap there. Starvation deaths also reset `startingCount` / `preBattleMaxCount` to the new count.
- **Card removal (AO-D026).** `REMOVE_CARD { instanceId }`; rules and prices are the constants in `run/cardRemoval.ts` (AO-D035, AO-D052; not on the Reward screen, AO-D068): Merchant = Gold, price rises per use (50 + 25 x uses); City (AO-D052) = free the first time, then 50, 100, 200, 400 ... Gold (`cityRemovalPrice(cityUses)`: `CARD_REMOVAL.city.firstPaidGold x growth^(paid uses)`), no daily limit; unaffordable is rejected and quoted as not allowed. Deck floor 5 cards. `cardRemovalQuote(run)` tells the UI whether/what. Counters live in `run.cardRemoval` (`merchantUses`, `cityUses`; old saves with `lastCityDay` migrate to one city use).
- **Food (AO-D048).** Each unit has `foodPerUnit` in `data/units.ts` (Swordsman/Goblin 0.1, Archer/Priest/Shaman/Wolf 0.2, Knight/Orc 0.5). Daily upkeep = the sum of `count x foodPerUnit` rounded to the nearest whole Food, at least 1 for a living army (`moveFoodCost(army, city)`, `dailyUpkeep(run)`, per-stack `stackUpkeep(stack)`), Stable -25% (round down, min 1). Every move is one day: Farm Food is added first, then the army eats, then Gold Mine Gold; A day the stockpile (plus Farm) cannot cover the upkeep starves the army (AO-D057): Food becomes 0 (the army is not cut down to what it can feed) and units die. UI helpers: `dailyProduction(run)`, `dailyFoodNet(run)`, `foodDaysLeft(run)` (full days before starving, Infinity if net is not negative), `foodWarning(run)` (true when starving is at most `FOOD_WARNING_DAYS` = 3 days away, or the army is already starving). `DAILY_INCOME { gold, food }` carries the Gold Mine and Farm payout. Balance targets (tested in `ao022.test.ts`): a starting army (8 units, also with Royal Banner) lasts 15+ days on the starting 50 Food with no Farm; Farm I covers it; Farm III balances a 38-unit army and leaves a 60-unit army at -5 Food/day; Stable keeps cutting 25%.

  **Starvation (AO-D057, `run/food.ts`, all numbers in the `STARVATION` block).** On a starving day `shortageRatio = deficit / dailyNeed` (0-1], `run.starvationDays` += 1 and `deaths = min(units - 1, max(1, ceil(lossRate x units)))` with `lossRate = min(0.6, (0.04 + 0.08 x shortageRatio) x (1 + 0.5 x (starvationDays - 1)))`: a fully starved first day is 12%, a 10% shortage about 5%, and each further day adds +50% of the day-1 rate (18/24/30/36% at full shortage). Units die one at a time, each drawn uniformly among all living units with the run RNG (`starveArmy`), so deaths spread across stacks and are deterministic per run; the last unit never dies. Event `STARVED { deaths: {unitId, count}[], day, consecutiveDays }`. The first fully fed day sets `run.starvationDays` to 0 (old saves migrate to 0). Morale: from `moraleAfterDays` = 3 consecutive starving days every player stack starts battles at `100 - starvationMoraleMalus(days)` (-10 on day 3, -8 more per further day, capped at -100 = Morale floor 0, reached on day 14); it is applied to the combat army only (`startBattleForRun`), the run army keeps its Morale and a won battle does not bake the malus in, so it vanishes as soon as the streak resets. Combat reads Morale in `damage.ts` (`moraleDamageMultiplier` x0.7-1.0, `moraleDefenseMultiplier` x0.85-1.0, both clamped to Morale 0-100), so the malus is visible (day 5 -26: x0.92 damage, day 10 -66: x0.80 damage). UI helpers: `starvationForecast(run)` (`willStarve`, `shortageRatio`, `lossShare`, `expectedDeaths`, `consecutiveDays`, `moraleMalus`, `moraleMalusIfStarves`), `starvationLossRate`, `starvationMoraleMalus`. Survivors from 0 Food with every day fully starved (mean over 300 seeds, totals do not vary by seed): 8 units 7/5/3/2/1, 38 units 33/27/20/14/8, 60 units 52/42/31/21/13 after days 1-5, Morale malus 0/0/-10/-18/-26 (days 6-10: -34/-42/-50/-58/-66).
